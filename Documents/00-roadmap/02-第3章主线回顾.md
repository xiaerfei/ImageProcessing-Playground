# 第 3 章主线回顾

> **这篇不讲新东西。** 它只做一件事:把已经写过的十几篇内容串成一条线,
> 让你知道哪些是**主干**(必须懂)、哪些是**细节**(踩坑时再查)。
>
> 什么时候看:学到一半觉得东西太多、串不起来的时候;或者隔了一阵回来复习的时候。

---

## 一、整章就这一个问题

第 3 章从头到尾,其实只在回答一个问题:

> **要算出一个像素的新值,得看多少东西?**

```
                    要算出一个像素的新值,得看多少东西?
                          /                    \
                   只看它自己                 还要看一圈邻居
                        ↓                          ↓
              塌缩成一张 256 项的表            必须现算 → 卷积
                  (3.2 点运算)                  (3.4~3.6 空间滤波)
                        ↓                          ↓
                  这张表哪儿来?                 打分表里填什么?
                        |                          |
        ┌───────────────┴──────────┐      ┌────────┴─────────┐
   公式给的                    图统计的     全是正数           有正有负
   线性 / 对数 / 伽马          直方图均衡    → 平滑(3.5)       → 锐化、找边(3.6)
   分段线性 / 阈值化            (3.3)        模糊、去噪          清楚、出轮廓
```

左边那一支,换的是**表里填什么数**;右边那一支,换的是**打分表里填什么数**。
就这么两件事,来来回回。

## 三、一条判据走遍全章

> **输出是否只取决于这个像素自己的值?**

这一条判据把整章劈成两半,而且每次都好用:

| 操作 | 只看自己? | 所以 |
| :--- | :---: | :--- |
| 线性 / 对数 / 伽马 / 分段线性 / 阈值化 | ✅ | 塌缩成 256 项的表 |
| 比特平面(单层) | ✅ | 也是表:`lut[v] = (v>>i)&1` |
| 直方图均衡化 | ✅ | **仍然是表** —— 只是先扫一遍图把表算出来 |
| CLAHE | ❌ | 还取决于**在哪儿** → 改成 64 张表 + 插值 |
| 模糊 / 锐化 / 找边缘 | ❌ | 要看邻居 → 只能卷积 |

> 一个很好的自检:实测在 `astronaut.png` 上做 5×5 高斯模糊,
> 原图里 653 个值同为 100 的像素,模糊后变成了 **67 种**不同的值。
> 一张表根本表达不了 —— 这就是「塌缩不了」的意思。

## 四、一条完整的实用链路

上面那些拼起来,就是一条能直接用的处理链:

```
   原图
    │
    ├─ 1. 先看家底        直方图 / 标准差 / 百分位跨度      3.3
    │                     诊断:偏暗?对比度不够?过曝?
    │
    ├─ 2. 先降噪          高斯 / 中值 / 双边                3.5
    │                     ⚠️ 一定在锐化之前,否则等于放大噪声再擦
    │
    ├─ 3. 调亮度对比度     伽马 / 自动色阶 / CLAHE           3.2、3.3
    │                     整体偏暗 → 伽马;光照不均 → CLAHE
    │
    ├─ 4. 再锐化          USM(不是裸拉普拉斯)              3.6
    │                     小半径小力度,盯着别出光晕
    │
    └─ 5. 要找东西        Sobel 梯度 / 阈值化               3.6、3.2
                          先平滑再求导,否则噪声全变成边
```

**顺序不能随便换**,这是本章最有实践价值的一条:

- 降噪必须在锐化**前** —— 锐化放大噪声 5.4 倍(拉普拉斯)或 1.86 倍(USM)
- 求导必须在平滑**后** —— Sobel 自带的 `[1,2,1]` 就是干这个的
- 对比度调整放中间 —— 太早会把噪声一起拉起来

## 五、每一节留下的那一句

如果每节只记一句话:

| 节 | 那一句 |
| :--- | :--- |
| **3.2 灰度变换** | 所有点运算最后都是一张 256 项的表;**表只能重排和合并灰度级,不能凭空造出新的** |
| **3.3 直方图** | 均衡化 = 「有百分之多少的人比我暗」× 255;**柱子不会真的变平**,离散图像做不到 |
| **3.3 CLAHE** | 一张表顾不了光照不均 → 切成 64 块各算各的,再用**双线性插值**接上 |
| **3.4 空间滤波** | 核是一张**打分表**;`cv2.filter2D` 做的是**相关**不是卷积(核不翻) |
| **3.5 平滑** | 四种做法只差在「怎么跟邻居商量」;**没有最好的,只有对不对症** |
| **3.6 锐化** | 锐化 = 原图 + 一份「细节」;**必然带来过冲和噪声放大**,所以要有旋钮(USM) |

## 六、看着吓人的细节

下面这些在文档里都写了,但**第一遍完全可以跳过**。
它们的价值是「哪天结果对不上时,有处可查」:

| 看着吓人的 | 其实是 | 什么时候才需要 |
| :--- | :--- | :--- |
| 相关 vs 卷积差 180° | 核对称时**没有任何区别** | 用方向性的核(Sobel)时 |
| `filter2D` 在 k≥9 改用 DFT | OpenCV 的实现细节 | 给大核做性能估算时 |
| OpenCV 的补边怪癖 | 一边除不尽两边都补 | 自己写实现想和 cv2 对齐时 |
| 均衡化要减 `cdf_min` | OpenCV 和教材公式差一点 | 手写均衡化对不上 cv2 时 |
| Scharr 的 `[3,10,3]` | 让梯度**方向**更准的一组数 | 要算边缘朝向、做特征匹配时 |
| σ 按勾股定理叠加 | 两次模糊怎么合成一次 | 需要精确控制模糊量时 |
| 秩 = 1 才能分离 | 「这张表是不是乘法口诀表」 | 自己设计核时 |

**判断标准很简单**:一个结论如果你没法一句话说清它解决什么问题,
那它多半就是细节,先放着。
