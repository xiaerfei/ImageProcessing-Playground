## 1. 规定化 / 匹配

**是什么**:均衡化是「摊平」,规定化是「变成我指定的分布」。
原理一句话 —— **两条 CDF 做反查表**:

$$ s = G^{-1}\big(F(r)\big) $$

`F` 是原图的 CDF,`G` 是目标图的 CDF。先用 `F` 把原值换算成「百分位」,
再问目标图「这个百分位对应哪个灰度」。均衡化其实是它的特例:目标分布取均匀分布时 `G⁻¹(p) = 255p`。

**为什么值得记**:比均衡化实用得多。最直接的用途是**多机位 / 多帧的色彩一致性** ——
两台相机拍同一场景色调不一样,拿一台的直方图当模板去套另一台,这就是转播里的粗对色。
遥感做多时相影像拼接、扫描件批量统一底色,都是这一招。

**局限**:只能逼近,做不准。桶不可拆分(同值像素必须一起走),
所以规定化后的直方图和目标直方图总有差距,色调对齐够用,别指望严丝合缝。

**回头查**:`np.interp` + 两条 `np.cumsum`;OpenCV 没有现成函数,
skimage 有 `skimage.exposure.match_histograms`。文档里的手算在
[06-histogram-matching.md](06-histogram-matching.md);
`15_histogram_deep_dive.py` 有个 demo。**从零实现留给脚本 `18`。**

## 2. 局部统计做增强

**是什么**:CLAHE 是「分块各做各的均衡」,教材还有另一套思路 ——
算出每个像素邻域的**局部均值和局部标准差**,拿它和全局值比,满足条件才增强:

```
如果 局部均值 < k0 · 全局均值        (这一片确实暗)
 且 k1·全局σ < 局部σ < k2·全局σ      (这一片有细节,但不是噪声)
则 该像素 × E                        (放大)
否则 原样不动
```

**为什么值得记**:它体现了一个更通用的思路 ——
**直方图不一定要拿来做映射表,也可以只拿来做判据**。
「先统计,再决定要不要处理、处理多狠」这个模式在后面到处都是(自适应阈值、自适应滤波)。

**回头查**:关键词「局部增强」「statistical enhancement」;
用 `cv2.boxFilter` 同时算 E[x] 和 E[x²],`σ² = E[x²] − E[x]²`,一次卷积搞定整幅图的局部统计。
**留给脚本 `19`。**

## 3. Otsu 阈值

**是什么**:直方图最经典的**非增强**用途 —— 自动找分割阈值。
穷举 0~255 每个候选阈值,把直方图切成两堆,算**类间方差**,取最大的那个:

$$ \sigma_b^2(t) = w_0(t)\,w_1(t)\,\big[\mu_0(t) - \mu_1(t)\big]^2 $$

最大化类间方差 ≡ 最小化类内方差,两者之和是常数(全图方差)。

**为什么值得记**:它是「直方图是双峰的 → 谷底就是前景背景的分界」这个直觉的严格版本,
而且只要 256 次循环,快到可以逐帧跑。双峰不明显时会失效 —— 这个失效条件本身也要记住。

**回头查**:`cv2.threshold(g, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)`;
自适应版本 `cv2.adaptiveThreshold`。
`05_piecewise_linear.py` 已经验证过「分段线性的 r1=r2 就退化成阈值化」,接上去正好。
**留给脚本 `07`(3.2 节还空着的那个号)。**

## 4. 直方图当特征用

这一条教材第 3 章完全不讲,但在工程里是直方图最常见的用法。
前面所有内容都是「统计直方图 → 算出一张表 → 改像素」;这里是「统计直方图 → 直接拿它当这张图的指纹」。

### 4.1 直方图对比

两张图的直方图有多像?四种常用度量:

| 方法 | OpenCV 常量 | 特点 |
| :--- | :--- | :--- |
| 相关性 | `HISTCMP_CORREL` | 1 = 完全相同,直觉最好 |
| 卡方 | `HISTCMP_CHISQR` | 对小差异敏感 |
| 交集 | `HISTCMP_INTERSECT` | 快,值越大越像 |
| Bhattacharyya | `HISTCMP_BHATTACHARYYA` | 0 = 完全相同,统计上最稳 |

**用途**:场景切换检测(转播切画面)、重复帧 / 静帧检测、镜头匹配、以图搜图的粗筛。
正好接上文档里那句「直方图丢了空间信息,但换来了便宜和旋转平移不变」——
**丢掉的东西恰恰是它作为特征的优点**。

**更讲究的度量**:EMD(Earth Mover's Distance,推土机距离)——
它知道「灰度 100 和 101」比「灰度 100 和 200」更接近,上面四种都不知道。
代价是慢。`cv2.EMD`。

### 4.2 反向投影

**是什么**:把目标物体的颜色直方图当成一张查找表,在整幅图上逐像素问
「你这个颜色在目标里出现得频繁吗」,输出一张概率图。

**用途**:CamShift / MeanShift 跟踪的基础;抠像前的粗定位;肤色检测。

**回头查**:`cv2.calcHist` → 归一化 → `cv2.calcBackProject` → `cv2.meanShift` / `cv2.CamShift`。
通常在 HSV 空间只用 H(和 S)通道,避开亮度变化。

## 5. 逐帧独立会闪烁

**是什么**:均衡化和 CLAHE 的表都是**从当前帧统计出来的**。
相邻两帧内容稍有变化(有人走过、云飘过),表就变,连续播放就是一闪一闪的亮度跳动。
[05-clahe.md](05-clahe.md) 里提了这一句,但**没有实测过**。

**怎么办**(三种,通常混用):

1. **时间平滑**:新表 = α·本帧表 + (1−α)·上一帧表,α 取 0.05~0.2
2. **降低更新频率**:每 N 帧才重算一次表,中间沿用
3. **干脆锁死**:开播前算一次,整场不变(直播里最常见的做法)

**为什么值得记**:这是「静态图算法直接搬到视频上」的通病,不止直方图 ——
自动白平衡、自动曝光、色调映射全都有同一个问题。
**任何「参数从当前帧统计出来」的算法,上视频前都要先想时域稳定性。**

**回头做**:合成一段缓慢变化的序列,逐帧独立均衡 vs 表做时间平滑,
把帧间平均亮度画成曲线,闪烁一眼就能看见。

## 6. 10/12 bit 与 HDR

**是什么**:到现在为止所有脚本都默认 8 bit —— 256 个桶、256 项 LUT、`cv2.LUT` 一次查完。
这条路在更高位深上会逐步走不通:

| 位深 | 桶数 | LUT 还能用吗 |
| :--- | :--- | :--- |
| 8 bit | 256 | 能,`cv2.LUT` 就是为它做的 |
| 10 bit | 1024 | 能,表大一点而已(HDR 视频、专业相机) |
| 12/16 bit | 4096 / 65536 | 勉强,但缓存不友好,通常改成粗表 + 插值 |
| 浮点(HDR/线性光) | 没有「档」 | **不能**。得自己定分桶范围,或者换成解析函数 |

**关键点**:
- `cv2.LUT` 支持 8 位和 16 位,但**表的长度写死**:8 位要 256 项,16 位要 65536 项,中间没挡位。
  10 bit 数据(装在 `uint16` 里只用 0~1023)要么建 65536 项的表白白浪费 64 倍,要么自己 `np.take` + 1024 项
- 浮点没有天然的桶,`np.histogram(x, bins=256, range=(lo, hi))` 的 `range` 要你自己定;
  HDR 图动态范围可能跨好几个数量级,通常先取 log 再分桶
- 位深越高,「同值像素不可拆分」这个限制越弱,均衡化反而更接近理论上的平坦

**为什么对你特别相关**:HDR / 10 bit 是转播的现实,
而「LUT 查表」这个在 3.2 学了六篇的核心手段,到 10 bit 就要重新考虑实现方式了。

## 7. ffmpeg 里的对应滤镜

把学到的概念映射到天天用的工具上:

| 学到的东西 | ffmpeg 滤镜 | 备注 |
| :--- | :--- | :--- |
| 全局直方图均衡化 | `histeq` | 有 `strength` / `intensity` 参数,不是纯教科书版 |
| 自动色阶(百分位裁剪) | `normalize` | 对应 [03-contrast.md](03-contrast.md) 第四节那一套 |
| 线性 / 幂律 / 分段线性 | `curves`、`eq`、`lut`、`lutyuv` | `eq` 的 gamma/contrast/brightness 就是 3.2 那几个旋钮 |
| 看直方图 | `histogram` | 实时画直方图,可叠加在画面上 |
| 分量图 / 波形图 | `waveform` | 对应 [02-histogram-reading.md](02-histogram-reading.md) 第三节的 Waveform |
| 矢量示波器 | `vectorscope` | 色度版本,直方图的二维亲戚 |
| CLAHE | **没有现成的** | 要么自己写 filter,要么走 OpenCV |

> 值得亲自跑一次的:
> `ffplay -i in.mp4 -vf "split[a][b];[b]histogram[c];[a][c]hstack"`
> —— 左边画面右边直方图,前面读的所有内容立刻就活了。
