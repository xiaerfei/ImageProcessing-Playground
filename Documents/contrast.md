# 对比度 —— 到底在说什么

> 面向零基础。配合 [histogram-transform.md](histogram-transform.md) 和 [intensity-and-grayscale.md](intensity-and-grayscale.md) 读。
> 文中数字可复现:`Python-Prototyping/Ch03_Spatial_Filtering/03_contrast_measures.py`

## 一句话

**亮度 = 整体多亮。对比度 = 亮的地方和暗的地方,差多少。**

一个说"平均值",一个说"差距"。**这是两件互不相干的事** —— 下面第二节会证明。

---

## 一、先分清亮度和对比度

拿两组数当作 5 个像素的亮度:

| | 像素值 | 平均 | 跨度(最大−最小) | 标准差 |
| :--- | :--- | :---: | :---: | :---: |
| **A 低对比度** | 100, 110, 120, 130, 140 | 120 | 40 | 14.1 |
| **B 高对比度** | 20, 70, 120, 170, 220 | 120 | **200** | **70.7** |

**平均值都是 120 —— 一样亮。** 但 B 的差距是 A 的 5 倍。

这就是对比度:**和亮不亮无关,只关心"拉得开不开"。**

### 加法改亮度,乘法改对比度

这条记住了,后面全通。

| 操作 | 结果 | 平均 | 跨度 |
| :--- | :--- | :---: | :---: |
| A 原样 | 100, 110, 120, 130, 140 | 120 | 40 |
| **A 整体 +100** | 200, 210, 220, 230, 240 | **220** ↑ | 40(不变) |
| **A 以 120 为中心 ×5** | 20, 70, 120, 170, 220 | 120(不变) | **200** ↑ |

- **加法**:所有值一起平移 → 只动平均值 → **只改亮度**
- **乘法**:所有值离中心的距离一起放大 → 只动跨度 → **只改对比度**

> 这正是那个线性变换公式 `s = a·r + b` 的含义:
> **`a` 是对比度旋钮,`b` 是亮度旋钮。**

---

## 二、为什么"直方图宽 = 对比度高"

直方图的横轴就是亮度。所以:

| 直方图长相 | 亮度 | 对比度 |
| :--- | :--- | :--- |
| 挤在左边一小段 | 暗 | 低 |
| 挤在右边一小段 | 亮 | 低 |
| **挤在中间一小段** | 不暗不亮 | **低** ← 就是"灰蒙蒙" |
| 铺满 0~255 | 中等 | 高 |

**柱子的位置** 决定亮度,**柱子的宽度** 决定对比度。两个维度分开看。

> **低对比度为什么看着"灰蒙蒙"**:因为所有东西的亮度都接近,物体和物体之间分不开,像蒙了层雾。
> 不是因为它"灰",是因为它"到处都一样"。

---

## 三、这个"差距"到底怎么统计

这才是关键问题。直觉上会说"最亮减最暗",但**这个定义有致命弱点**。

### `max − min` 会被两个像素骗过

我造了一张 10000 像素的图:

- **全部是 120 的纯灰**(看上去就是一块均匀灰板,什么都看不见)
- 只把**其中 2 个像素**改成 0 和 255(占 0.02%)

| | 跨度(max−min) | 标准差 | 1~99% 跨度 |
| :--- | :---: | :---: | :---: |
| 纯灰 + 2 个极端点 | **255** | **1.81** | **0.0** |
| 真·高对比度渐变 | **255** | **73.62** | **249.9** |
| 纯灰(无极端点) | 0 | 0.00 | 0.0 |

**跨度这个指标完全瞎了** —— 两张图都报 255,但一张是均匀灰板,一张是完整渐变。

而标准差 **1.81 vs 73.62,差 40 倍**;百分位跨度 **0.0 vs 249.9**,判断完全正确。

**所以实际统计根本不用 `max − min`。**

### 办法一:标准差(RMS 对比度)—— 最常用

不看两个端点,而是问:**每个像素离平均值有多远,把所有像素的偏离量平均起来。**

```
标准差 = √( 平均[(每个像素 − 全图平均值)²] )
```

关键在于**每个像素都参与**。那 2 个极端点在 10000 个像素里被稀释掉了。

> **为什么要平方再开方**:直接算"偏离量的平均"的话,正偏离和负偏离会互相抵消,永远是 0。
> 平方先把负号消掉(负数平方变正),最后开方把量纲变回来(不然单位就成了"亮度的平方")。

正式名字叫 **RMS contrast**(均方根对比度)。日常说"这张图对比度高",指的基本就是标准差大。

### 办法二:百分位跨度 —— 工程上最实用

思路更朴素:**把最极端的那一小撮直接扔掉再算。**

不问"最亮和最暗差多少",改问:

> **第 99% 亮的像素,和第 1% 亮的像素,差多少?**

上面那张假图的 1~99% 跨度是 **0.0** —— 那 2 个极端点连 1% 都占不到,直接被扔了。

### 三种度量对照

| 度量 | 公式 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **跨度** | `max − min` | 最直觉 | **一个坏点就毁了** |
| **标准差(RMS)** | 亮度的标准差 | 稳健,每个像素都算 | 对"分布形状"不敏感 |
| **百分位跨度** | `P99 − P1` | 稳健,且直接对应"该拉到哪" | 要选百分位阈值 |
| **Michelson** | `(max−min)/(max+min)` | 光学、周期条纹的标准 | 同样怕极端值 |
| **Weber** | `(前景−背景)/背景` | 单个物体贴在背景上 | 需要先分出前景 |

前三个是图像处理里的日常,后两个用在特定场景。

## 四、这不是理论 —— 自动色阶就靠它

Photoshop 的**自动色阶**、ImageMagick 的 `-contrast-stretch`、各种"一键增强",内部干的就是百分位裁剪:

```
1. 找出第 0.5% 和第 99.5% 分位的亮度值(不是 min 和 max)
2. 把这两个值拉伸到 0 和 255
3. 超出的那 1% 直接裁掉
```

### 为什么要故意扔掉 1% —— 实测

造一个真实场景:**隔着雾拍的低对比度照片,画面里有一个反光高光和一个暗坏点**。

| | 标准差 | 效果 |
| :--- | :---: | :--- |
| 原图(灰蒙蒙 + 坏点) | 22.51 | 待增强 |
| **按 min/max 拉伸** | **22.51** | **等于没做** |
| **按 0.5~99.5% 拉伸** | **75.33** | **涨了 3.3 倍** |

`min/max` 方案为什么失效:**那两个坏点已经占住了 0 和 255**,算法一看"哦,已经铺满整个范围了",于是什么都不做。

真实照片里几乎总有这种坏点:

- 传感器热噪声的孤立亮点
- 灯泡、水面、金属的镜面反光(本来就该是死白)
- 压缩噪声

**一个太阳的反光就能让整张图的自动增强失效。** 所以那 1% 必须扔。

## 五、直方图均衡化为什么天然免疫

它用的是 **CDF(累计比例)**,而不是端点。

那 2 个极端像素在累计比例里只占 0.02%,CDF 几乎不动。**它是按"有多少像素"分配的,不是按"值有多极端"分配的。**

这也解释了均衡化的一个特点:虽然"没法调参"很讨厌,但**鲁棒性极好** —— 它压根不看极端值。

> 均衡化的原理见 [histogram-transform.md](histogram-transform.md) 第十节。

## 六、显示器上的"对比度"

这里藏着**三个不同的东西都叫对比度**,混在一起就糊涂了。

### 1. 旋钮上的"对比度" —— 就是上面的 `a`

显示器那两个旋钮,本来就是按加法/乘法分工的,命名来自 CRT 时代:

| 旋钮 | 干什么 | 对应 |
| :--- | :--- | :--- |
| **亮度 (Brightness)** | 调**黑电平** —— 黑色到底有多黑 | **`b`,加法** |
| **对比度 (Contrast)** | 调**增益** —— 信号放大多少倍 | **`a`,乘法** |

调过头的后果和图像处理里一模一样:

- **对比度太高** → 亮部压到 255 → 白色细节糊成死白(白衬衫看不出褶皱)
- **亮度太高** → 黑色被抬起来 → 画面发白发飘,暗部没层次

> ⚠️ **一个坑**:现在很多液晶显示器的"亮度"旋钮,调的其实是**背光灯功率**,不是黑电平。
> 这是厂商偷换了概念 —— 它更像"整个屏幕多亮"。所以你调它的时候黑色也跟着变亮(背光漏光),行为和 CRT 时代不一样。

### 2. 规格表上的"对比度 1000:1" —— 硬件能力,调不了

它叫**对比度比 (contrast ratio)**:

```
屏幕能显示的最白 ÷ 屏幕能显示的最黑
```

这是**物理能力上限**,买回来就定死了。

- **普通 LCD**:约 1000:1。液晶挡不住全部背光,"黑"其实是很暗的灰,永远漏一点光
- **OLED**:理论上无穷大。黑色是像素**直接关掉**,一点光都不发,所以是"真黑"

> 暗房里看液晶电视,黑边是灰的;看 OLED,黑边和外壳融为一体 —— 就是这个差别。

**"动态对比度 3000000:1"** 是营销话术:分子是"最亮画面时的白",分母是"最暗画面时把背光关掉的黑",**两个数不在同一时刻测**,没有意义。

### 3. 图像本身的对比度 —— 前五节讲的那个

### 三者的关系

> **图像的对比度** = 乐谱上写的强弱变化有多大
> **显示器的对比度旋钮** = 功放的增益,你可以再放大一点
> **对比度比 1000:1** = 这套音响最响和最轻能拉开多少,**物理上限**

所以:

- 一张灰蒙蒙的照片,**在再好的 OLED 上还是灰蒙蒙的** —— 内容里没有的东西,屏幕变不出来
- 一张高对比度的照片,**在对比度比只有 300:1 的老屏幕上会发灰** —— 内容有,屏幕表现不出来

### 怎么调才对

用测试图(搜 "black level test pattern" / "white clipping test"):

1. **先调对比度**:找一张大面积白色渐变的图,往上加到**刚好还能分辨出最亮那几级灰**,再往上就并成死白 —— 退回来一点
2. **再调亮度**:找一张大面积黑色渐变的图,往下降到**刚好还能分辨出最暗那几级灰**,再往下就全黑 —— 停在那

**两个都是"顶到能看见细节的边缘,再退半步"** —— 和摄影里判断直方图有没有被切断,完全是同一个思路。

> 如果"亮度"调的是背光,那它应该按**环境光**定:暗房间调低、白天调高,这是为了眼睛舒服,和画质无关。
> 真正影响画质的黑电平往往藏在别的菜单里。

## 小结

| 问题 | 答案 |
| :--- | :--- |
| 对比度是什么 | 亮的地方和暗的地方差多少,**与整体亮度无关** |
| 怎么改 | **加法改亮度,乘法改对比度**(`s = a·r + b`) |
| 直方图上怎么看 | **位置**看亮度,**宽度**看对比度 |
| 差距怎么统计 | **不用 max−min**,用标准差或百分位跨度 |
| 为什么不用 max−min | 两个极端像素就能骗过它(实测 1.81 和 73.62 都报 255) |
| 自动色阶为什么扔 1% | 一个反光坏点就能让拉伸失效(22.51 → 22.51 vs 22.51 → 75.33) |
| 均衡化为什么免疫 | 它看 CDF(按像素数分配),不看极端值 |
| 显示器旋钮 | 对比度 = 增益(`a`),亮度 = 黑电平(`b`) |
| 规格表 1000:1 | 硬件上限,和旋钮无关;OLED 因黑色关灯而趋于无穷 |
