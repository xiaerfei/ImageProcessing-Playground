## 写作约定

这套笔记面向零基础自学,也要能直接印成 PDF,所以标题有硬性约定:

| 级别 | 用途 | 长度上限 | 规矩 |
| :--- | :--- | :--- | :--- |
| `#` | 篇名,一篇只有一个 | 12 个汉字 | 纯名词短语。不带破折号副标题 |
| `##` | 节,形如 `三、xxx` | 序号外 10 个汉字 | 破折号后面那半句是正文,搬到节下第一行 |
| `###` | 小节 | 12 个汉字 | 不带 emoji、不带 ⚠️、不把整句话当标题 |
| `####` | 只在小节内部再分层时用 | 12 个汉字 | 不进 PDF 书签 |

其它约定:

- **每篇开头带一张「怎么读这篇」三档表**(只有 10 分钟 / 第一遍学 / 踩坑时回来查),
  把「第一遍必须懂的」和「将来查阅的」分开标出来。
- **一个主题只在一处说完。** 不要「前面讲一半、后面再讲一半」——
  宁可把篇拆开,也不要在同一篇里隔着几百行讲同一个东西。
- 先给生活化的类比,再上术语和公式;公式段落标注「公式版,可跳过」,后面跟一句「这在说什么」。
- **按「理解顺序」编排,不是教材顺序也不是实现顺序**:
  先讲为什么需要它 → 再讲它怎么做 → 最后讲它的代价和边界。
- **专业名词第一次出现时要带英文**,格式是 `中文(english)`,例如
  `相关(correlation)`、`卷积(convolution)`。理由很实在:
  **中文译名不统一而英文只有一个** —— 同一个 unsharp masking,
  中文书里叫「反锐化掩模」「钝化蒙版」「钝化掩蔽」的都有,
  不记英文,以后读论文会对不上号。

  规矩:**每篇只在第一次出现时标一次**(标多了是噪声);
  **标题、表格、引用块里不标**(会撑长 PDF 书签、挤爆单元格);
  一个词的英文已经在旁边出现过(比如 `CLAHE = Contrast Limited…`)就不用再标。
  全部术语另有一份 [00-roadmap/04-术语对照表.md](00-roadmap/04-术语对照表.md)。
- **每一种处理方法都要配图,而且配图要成套回答五个问题**
  (`Python-Prototyping/figkit.py` 的 `four_questions()` 会把它画成一条五色横幅):

  | 问题 | 图上要能看见什么 |
  | :--- | :--- |
  | **做了什么** | 这一步到底动了什么(前后对照、中间量、映射曲线) |
  | **得到什么** | 收益,而且要量化 |
  | **失去什么** | 代价。**和收益画在同一张图里**,不要分成两张 |
  | **局限在哪** | 优先用反例:挑一张它会翻车的图跑一遍,让人看见它翻车 |
  | **更好的做法** | **只点名,不展开**。知道「还有路可走、该往哪儿查」就够了 |

  最后一格是必填的,不是可选项 —— 写不出出路,通常说明「局限」那一格还没想清楚。
  正文里讲完局限之后也照此办理:补一句「想做得更好,看 xxx」,一句话带过。

- 数字都来自 `Python-Prototyping/` 下可复现的脚本,引用时写明是哪一个;
  **图里的数字必须和正文表格逐个吻合**(跑完脚本核对一遍)。

- **每个算法都先给伪代码,再给真代码。** 伪代码回答「它一共分几步」,
  真代码回答「每一步具体怎么写」。两者分工明确,不要用真代码兼任骨架 ——
  真代码里混着类型转换、边界判断、性能技巧,第一遍读会被淹没。

  格式统一成下面这样,用 ` ```text ` 围栏(**不要用 ```python**,
  否则语法高亮会暗示它能直接跑):

  ```text
  算法:直方图均衡化
  输入:灰度图 img(每个像素 0~255)
  输出:均衡后的图

  1. hist ← 数一遍 img 里每个灰度各出现了几次        // 256 个桶
  2. cdf  ← hist 从左到右逐项累加,再除以总像素数     // 「比我暗的占多少」
  3. 对每个灰度 r(0~255):
         lut[r] ← round(255 × cdf[r])
  4. 对每张图的每个像素 p:
         输出[p] ← lut[ img[p] ]
  ```

  约定:`←` 表示赋值,`//` 后面是注释,缩进表示从属关系,
  **不写类型、不写内存管理、不写边界特判** —— 那些留给真代码。
  伪代码块后面紧跟一句「这一步为什么在这儿」,别让它孤零零地立着。
