## 附:`00_yuv_warmup.py` 转换原理详解

> 这一节把脚本里 `i420_to_rgb()` 的三行公式从头推导一遍。
> 记住结论:**背 Kr、Kb 两个数,就能写出任何标准的 YUV↔RGB,不需要背矩阵。**

### 0. 为什么会有 YUV

两个原因,一个历史的、一个生理的:

1. **向下兼容黑白电视**(历史):彩色电视信号必须让黑白电视机也能收看。方案:继续广播亮度信号 Y,把颜色作为两个额外的"色差"信号叠加上去——黑白机只解 Y,彩色机多解两路色差。
2. **人眼对亮度敏感、对色度迟钝**(生理):视网膜上感知明暗的杆状细胞远多于感知颜色的锥状细胞。把亮度与色度分离后,色度可以用更低的分辨率/带宽传输而人眼几乎无感——这就是 4:2:0 色度下采样的依据,也是"省一半数据"的来源。

### 1. 第一步:亮度是 R′G′B′ 的加权和

$$Y' = K_r \cdot R' + K_g \cdot G' + K_b \cdot B', \qquad K_r + K_g + K_b = 1$$

- 权重反映人眼对三种原色的**亮度贡献感知**:绿色看起来最亮,所以 $K_g$ 最大。
- 不同标准的显示三基色(色域)不同,同样的"感知亮度"分解出的权重就不同:

| 标准 | $K_r$ | $K_b$ | $K_g = 1-K_r-K_b$ | 场景 |
| :--- | :--- | :--- | :--- | :--- |
| BT.601 | 0.299 | 0.114 | 0.587 | SD 标清 |
| BT.709 | 0.2126 | 0.0722 | 0.7152 | HD 高清 |
| BT.2020 | 0.2627 | 0.0593 | 0.6780 | UHD/HDR |

- **注意撇号**:$R'G'B'$ 是 gamma 编码后的值(0~1)。工程上的 Y′ 叫 **luma**,是对非线性值的加权;物理上的亮度 luminance 要在线性光下算。视频管线几乎都在非线性域做这件事(简单、够用),但要知道两者不是一回事。

### 2. 第二步:色度 = 归一化的色差

有了 Y′,颜色信息只需再传两路。选**色差** $B'-Y'$ 和 $R'-Y'$(G′ 可以由三者反解出来,不用传)。

色差的取值范围不对称,需要归一化。以 $B'-Y'$ 为例求范围:

- 最大:纯蓝 $(R',G',B')=(0,0,1)$ 时,$Y'=K_b$,故 $B'-Y' = 1-K_b$
- 最小:黄色 $(1,1,0)$ 时,$Y'=K_r+K_g=1-K_b$,故 $B'-Y' = -(1-K_b)$

即范围是 $\pm(1-K_b)$。除以 $2(1-K_b)$ 就归一到 $\pm 0.5$:

$$C_b = \frac{B'-Y'}{2(1-K_b)}, \qquad C_r = \frac{R'-Y'}{2(1-K_r)}$$

> 教科书里的"魔法数字"由此而来:BT.601 的 $2(1-K_r) = 2 \times 0.701 = 1.402$、$2(1-K_b) = 2 \times 0.886 = 1.772$——就是常见公式 `R = Y + 1.402·Cr` 里的系数。它们不是需要背的常数,是 $K_r$、$K_b$ 的函数。

### 3. 第三步:反变换(代码里的三行)

由上面两组定义直接反解:

$$R' = Y' + 2(1-K_r) \cdot C_r$$
$$B' = Y' + 2(1-K_b) \cdot C_b$$
$$G' = \frac{Y' - K_r R' - K_b B'}{K_g}$$

第三行就是亮度定义式移项:已知 Y′ 和刚解出的 R′、B′,剩下的只能是 G′ 的贡献。对应 `i420_to_rgb()`:

```python
r = yn + 2.0 * (1.0 - kr) * cr
b = yn + 2.0 * (1.0 - kb) * cb
g = (yn - kr * r - kb * b) / kg
```

### 4. 第四步:量化到 8bit —— range 的来历

上面全是 0~1(色差 ±0.5)的连续值,存成 uint8 有两种约定:

| | Y | Cb/Cr | 反量化 |
| :--- | :--- | :--- | :--- |
| **full range** | $\lfloor 255 \cdot Y' \rceil$,0~255 | $128 + 255 \cdot C$ | $Y'=Y/255$,$C=(C_{8bit}-128)/255$ |
| **video range** | $16 + 219 \cdot Y'$,16~235 | $128 + 224 \cdot C$,16~240 | $Y'=(Y-16)/219$,$C=(C_{8bit}-128)/224$ |

video range(又叫 limited/studio range)的 16/235 是模拟广播时代留下的:同步脉冲占用电平两端,且滤波会产生过冲,需要 headroom/footroom;数字化(BT.601)时保留了这个约定,SDI/广播链路沿用至今。

**错配症状速查**(第 8 周会专门做实验):
- video 数据按 full 解读 → 黑不够黑、白不够白,画面**发灰**
- full 数据按 video 解读 → 对比度拉爆,**暗部死黑、高光剪切**
- 601/709 矩阵混用 → 亮度基本没事,**肤色/橙绿色偏**(误差集中在色度)

### 5. 验证:推导值 vs 脚本实测值

用第 1~4 步手算纯色(BT.601 + video range),对照 `00_yuv_warmup.py` 侦探实验的实测输出:

| 输入 RGB | 计算 Y | 计算 U | 计算 V | 实测 (Y, U, V) |
| :--- | :--- | :--- | :--- | :--- |
| 红 (255,0,0) | $16+219 \times 0.299 = 81.5$ | $128 - 224 \times \frac{0.299}{1.772} = 90.2$ | $128 + 224 \times 0.5 = 240$ | (82, 90, 240) ✅ |
| 绿 (0,255,0) | $16+219 \times 0.587 = 144.6$ | $128 - 224 \times \frac{0.587}{1.772} = 53.8$ | $128 - 224 \times \frac{0.587}{1.402} = 34.2$ | (145, 54, 34) ✅ |
| 蓝 (0,0,255) | $16+219 \times 0.114 = 41.0$ | $128 + 224 \times 0.5 = 240$ | $128 - 224 \times \frac{0.114}{1.402} = 109.8$ | (41, 240, 110) ✅ |
| 白 (255,255,255) | $16+219 = 235$ | 128 | 128 | (235, 128, 128) ✅ |

全部吻合(±取整)——这就是脚本判定 OpenCV 的 I420 转换为 **BT.601 + video range** 的依据,也反过来证明上面的推导没错。

### 6. 最后一环:4:2:0 与色度上采样

I420 里每 2×2 个像素共用一对 (U, V),解码回 RGB 前要把色度平面放大回全分辨率。脚本用最近邻(`np.repeat` 两次);实验中手写解码与 OpenCV 最大误差仅为 1,说明 OpenCV 内部也是最近邻。更讲究的实现会用双线性上采样,色块边缘的"溢色"会更柔和——这留到第 8 周的 `02_yuv_pitfalls.py` 观察。
